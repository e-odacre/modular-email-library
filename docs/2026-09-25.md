## UI and automation session

### Reference and decisions

- Read the Agency app's workflow and design implementation without modifying it.
- Adopted its compact semantic daisyUI styling and local-agent prompt handoff.
- Chose structured, file-backed email builds, with no new AI API dependency,
  queue, account system, or database model.
- Preserved Evan's daisyUI installation and `/test` component demonstration.

### Workspace

- Added a responsive sidebar, overview counts, workflow guidance, brand cards,
  build review list, mobile navigation, and keyboard skip link.
- Added Dim/Light appearance switching with browser persistence. This preference
  is separate from the email renderer's style selection.
- Added searchable libraries, category filters, persistent grid/list preference,
  incremental results, lazy preview thumbnails, and source-change refresh.
- Added email review with desktop/phone widths, style selection, component
  variants, component field/settings information, HTML size, and diagnostics.
- Integrated SanEcoTec into native brand/library/review pages while preserving
  its original static gallery, source references, compositions, and downloads.

### Brief and local-agent handoff

- Added New email / Build brief with name, unique build ID, brand, recipe, style,
  audience, objective, approved content, and optional HTTP(S) CTA destination.
- Added browser-local brief autosave, validation, and reset. Source polling is
  disabled on the form so a refresh cannot erase ongoing edits.
- Generate a copyable/downloadable prompt containing source references, content
  constraints, expected JSON output, and validation commands.
- The user runs the prompt with a local agent in this repository. The application
  does not launch the agent or claim generation has completed.

### Engine and builds

- Discover `email-engine/drafts/<build-id>.json` and support either recipe/data
  builds or ordered component-node compositions.
- Added `npm run email:check -- <build-id>` and bridge collection operations.
- Validate IDs, file size, schema, brand/style, MJML, and existing email checks.
  Reject executable email output and retain draft-token warnings.
- Show malformed builds for repair and block preview/export when errors exist.
- Reject duplicate build IDs at brief submission; generated prompts also instruct
  the agent not to overwrite existing source files.
- Preserve clean HTML downloads and production-token validation boundaries.

## Current boundaries and next starting point

- Briefs are saved in this browser, not in a shared database. JSON build sources
  are versioned files; generation runs in the user's local coding agent.
- There is no drag-and-drop editor, automatic email sending, or Klaviyo API
  delivery. Renderer success is not content approval or inbox testing.
- SanEcoTec still contains unresolved draft values requiring review.
- Only Dim and Light workspace themes are enabled. Another daisyUI theme needs
  CSS registration, the layout's saved-theme allowlist, and the switcher updated.
- No first real email build has been authored in this session. The next practical
  step is to prepare a real brief, run its prompt, and review the resulting build.
- Future sessions should add a dated entry and update [progress.md](progress.md).
